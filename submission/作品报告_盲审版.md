# 银龄健康通——面向老年人的 AI 健康教育与就医协同助手

> 作品赛盲审版材料。本文不包含学校、团队、指导教师和个人信息。

## 一、项目摘要

老年人在面对健康信息时，常见困难不是完全没有信息，而是信息太专业、不会组织就医材料、想问医生却不知道如何开口，子女也难以及时了解情况。本作品以大模型自然语言交互为入口，让老年人用简单文字或语音提出健康问题，系统使用通俗语言讲解，并自动整理就医准备清单、问诊问题清单和家属提醒。

项目定位为健康教育和就医协同工具，不做疾病诊断和治疗决策。作品采用本地可运行的网页原型，支持无模型密钥的演示模式，能够在一周内完成部署和现场展示。

## 二、问题分析与用户需求

### 1. 老年人的信息理解困难

“血压管理”“复诊资料”“药物注意事项”等内容经常使用专业术语。老年人需要的是短句、重点和下一步行动，而不是一大段医学说明。

### 2. 就医前准备不充分

忘记携带既往检查报告、药盒或血压记录，会降低问诊效率。一个简单的清单比临时回忆更可靠。

### 3. 老人和家属之间存在信息断点

老人问过什么、医生需要了解什么、下一步要做什么，家属不一定能够及时掌握。系统生成一段家属提醒，可以降低沟通成本。

## 三、解决方案

系统页面只有一个主要入口：输入或说出问题。回答固定分为四个层次：

1. 用一句简单的话解释问题。
2. 列出日常可以注意的事项。
3. 提示什么情况应及时咨询医生或就医。
4. 生成就医清单、问诊问题和家属提醒。

页面使用大字号、高对比度颜色、明显按钮和朗读功能。浏览器不支持语音时，仍然可以使用文字输入完成全部流程。

## 四、大模型应用方式

大模型承担三项工作：

- 将用户的口语化问题整理成适合回答的意图。
- 结合预置健康知识，改写成老人容易理解的短句。
- 按固定结构生成清单和家属提醒，避免只返回一段不易执行的长文本。

系统先进行输入检查和高风险词识别，再给模型提供经过人工整理的参考知识。输出经过字段校验；模型服务不可用或返回格式异常时，自动回退到本地演示内容。

## 五、技术路线

```text
浏览器文字/语音
       ↓
Flask /api/ask
       ↓
问题校验与安全边界检查
       ↓
JSON 健康知识检索
       ↓
OpenAI 兼容大模型或本地演示模式
       ↓
结构化回答、清单、家属提醒
       ↓
网页展示、朗读、复制
```

后端使用 Python Flask，前端使用原生 HTML、CSS 和 JavaScript，数据使用 JSON 文件保存。项目不接入真实医院系统，不保存姓名、身份证号、病历号等身份信息。

## 六、创新点

### 1. 从“回答问题”延伸到“帮助行动”

普通问答往往停留在知识解释。本作品进一步生成就医准备清单和问诊问题，使回答可以直接转化为下一步行动。

### 2. 以老年人的表达方式为入口

老人不需要学习复杂菜单，只需要说出“血压高要注意什么”“去医院要带什么”。系统负责把口语问题整理成易懂内容。

### 3. 同时服务老人和家属

老人得到易懂的解释，家属得到可复制的提醒，形成轻量协同。

### 4. 低门槛、可离线演示

不依赖复杂硬件和长期数据积累。没有 API 密钥时仍可用演示模式展示完整流程，有利于教学场景和比赛现场使用。

## 七、安全设计

- 不输出疾病诊断结论。
- 不建议自行停药、加药、减药或替换药物。
- 不做处方、药盒和检查报告自动识别。
- 对胸痛、呼吸困难、意识不清等表达给出及时急诊提示。
- 页面持续展示“健康科普不能替代医生诊断”的提示。
- 模型接口失败时回退到可控的人工整理内容。
- 不保存真实个人健康信息。

## 八、测试与演示结果

项目自动化测试覆盖：空问题校验、高风险问题识别、演示回答结构和完整字段输出。现场演示使用高血压、感冒发热和自行停药三个问题，分别展示健康教育、就医清单和安全边界。

## 九、社会价值

作品面向人口老龄化背景下的真实沟通场景，把大模型能力转化为老年人看得懂、家属用得上、社区容易推广的服务。它不能替代医生，但可以减少健康知识理解和就医准备中的障碍，帮助有限的医疗沟通时间被更有效地使用。

## 十、局限与后续改进

当前版本的知识库规模较小，语音识别效果受浏览器和环境影响，家属提醒暂时通过复制文字完成。后续可以在专业人员审核下扩充健康教育知识，增加方言语音、社区工作人员端、用药记录和可审计的知识来源，但仍保持不做诊断和自动改药的边界。
