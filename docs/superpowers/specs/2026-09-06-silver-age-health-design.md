# 银龄健康通设计说明

## 1. 项目定位

项目名称：银龄健康通——面向老年人的 AI 健康教育与就医协同助手。

项目面向老年人、子女和社区工作人员，聚焦“听得懂、问得清、带得全、家属知情”四个问题。系统只提供健康科普、就医准备和家属沟通辅助，不做疾病诊断、处方识别、药量调整或治疗决策。

按安徽省 AI 大模型创新应用竞赛目前可见的校方通知，本项目申报作品赛中的智能交互/对话方向，同时体现知识管理与内容生成能力。演示作品和材料不写入学校、团队、指导教师或个人信息，便于后续制作盲审版本。

## 2. 一周 MVP 范围

老人可以用文字提问，或通过浏览器中文语音识别输入问题。系统使用通俗语言回答，并固定输出四部分：

1. 简单解释：避免专业术语，必要时解释术语。
2. 日常注意：给出低风险、可执行的健康教育建议。
3. 什么时候就医：只做风险提示，不替医生判断。
4. 下一步准备：生成就医准备清单、问诊问题清单和家属提醒。

项目提供大字号、高对比度、清晰按钮和“朗读回答”功能。家属提醒先生成可复制文本，不开发短信、微信或账号系统。

## 3. 使用流程

```text
老人语音/文字提问
        ↓
安全边界检查 + 健康知识检索
        ↓
大模型生成通俗回答与结构化清单
        ↓
页面展示 / 朗读 / 复制家属提醒
```

系统预置少量经过人工整理的高频健康教育知识，包括高血压、糖尿病、感冒发热、就医准备和用药记录。检索仅用于给模型提供背景，不把知识库当作诊断依据。

## 4. 技术方案

- 后端：Python Flask。
- 前端：原生 HTML、CSS 和 JavaScript，减少依赖，突出老年友好界面。
- 语音：浏览器 SpeechRecognition / webkitSpeechRecognition；不支持时保留文字输入。
- 大模型：使用 OpenAI 兼容的 Chat Completions 接口；没有 API 密钥时使用本地演示模式，保证离线答辩可运行。
- 数据：JSON 知识库和内存会话，不接入真实个人健康数据。
- 输出：统一为 JSON 结构，包含 answer、attention、when_to_seek_care、visit_checklist、doctor_questions、family_message 和 safety_note。

## 5. 安全和异常处理

- 为空问题返回明确提示，不调用模型。
- 检测到“诊断、改药、停药、药量、急救”等高风险表达时，回答中加入“不能替代医生”的边界说明，并引导就医；不生成具体治疗决定。
- 模型接口不可用、返回格式错误或超时时，自动回退到演示模式，并在界面标注“演示数据”。
- 不保存姓名、身份证号、病历号等身份信息；输入只在当前页面会话中处理。
- 所有回答页面都显示健康科普免责声明。

## 6. 验收标准

- 在没有 API 密钥时可启动并完成至少三个演示问题。
- 文字提问可以得到回答、三类清单和安全提示。
- 中文语音按钮在支持浏览器中能把语音转成问题文本；不支持时不影响文字流程。
- 页面在桌面浏览器中具备大字号和明显操作反馈。
- 自动化测试覆盖空问题、高风险问题、演示回答结构和家属提醒生成。
- README 能让新用户在五分钟内启动项目。
- 作品报告、答辩大纲、演示脚本和技术说明不包含身份信息。

## 7. 明确不做的内容

- 不做疾病诊断和概率判断。
- 不做处方、药盒或检查报告的自动识别。
- 不做真实医院、医保或微信接口对接。
- 不做账号、支付、消息推送和长期病历存储。
- 不复制开源项目代码，仅借鉴 Calendula、Dosage 等开源项目的提醒与记录思路，并在材料中注明参考来源。
